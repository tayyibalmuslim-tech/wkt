# صفوف المهام المباشرة

تنفيذ على `ui-redesign` بعد المرحلة 5. يجمع هذا الطلب أيضًا إصلاح توسيط نافذة تسجيل الخانات من PR #10؛ لم تُدمج هذه التغييرات إلى main أثناء التنفيذ.

## ما تغير

- صف موحد في المشاريع ولوحة المهام والقوائم العامة: فعلتها، لم أفعلها، تعديل، الخانات المنجزة/المتوقعة، والترتيب ظاهرة دائمًا. لا اختيار مسبق ولا hover ولا تمدد لإظهارها. الحذف وإضافة فرع فقط في قائمة ثانوية عائمة.
- ارتفاع الأصل على الكمبيوتر نحو 45px والفرع نحو 37px. الاسم والوصف متجاوران مع اختصار؛ زر الاسم يعرض النص الكامل في نافذة صغيرة مشتركة لا تغيّر ارتفاع القائمة.
- على الهاتف، مساحة 320px لا تكفي للاسم وخمسة أهداف لمس بعرض 40px في سطر واحد مقروء. لذلك الصف ثابت بمسارين، نحو 84px: الاسم ثم الأدوات الظاهرة دائمًا، دون تمدد عند التفاعل أو تجاوز أفقي للصفحة. هذا اختلاف مقصود عن السطر الأفقي الواحد على الكمبيوتر.
- الفروع مغلقة افتراضيًا وتُنشأ عند الفتح فقط، مع خط جانبي ومسافة بادئة محدودة، وعداد المكتمل/الإجمالي. التوسيع محفوظ عند النتيجة والخانات والترتيب والعودة من المحرر.
- النتيجة بضغطة واحدة، والضغط ثانية يلغيها. تحديث الصفوف المعروضة للأصل والفروع والمشاريع المشتركة موضعي. الخانات تُحفظ عند Enter أو المغادرة، مع رفض الكسور والأرقام السالبة والفراغ وما يتجاوز 9999؛ مسموح بتجاوز المستهدف وفق المنطق الحالي.
- الترتيب يحرك عناصر DOM القائمة، ويحفظ التركيز والتمرير. قلم الفرع يفتح محرره مباشرة ويعيد المستخدم إلى سياق القائمة بعد الحفظ. قوائم النتائج المفلترة قد تعيد بناء قسم النتائج عند تغير عضويته؛ الصفحة الكاملة لا يعاد رسمها لتسجيل النتيجة أو الخانات.

## البيانات والتوافق

ترتيب المشروع يبقى في `project.taskOrder`، وترتيب الإخوة في `subtaskPosition`. أُضيف حقل اختياري واحد `listPosition` عند ترتيب الأصول في القوائم العامة، لأن الطلب يمنع رقم ترتيب بلا وظيفة. يشمل ترتيب القوائم العامة الأصول المسجلة عبر القوائم والتواريخ، وتعرض تلميحاته هذا النطاق. غياب الحقل يحافظ على الترتيب الافتراضي القديم. لا يتغير ترتيب المشروع المستقل أو الأولوية أو الموعد أو النتائج. لا نسخ للمهام المشتركة.

لا تغيير لمسارات Firebase أو قواعده أو غلاف الاستيراد والتصدير أو حسابات التقدم. الحقل الاختياري ينتقل مع سجل المهمة في النسخ والمزامنة المعتادة. لا تعديل لـREADME أو vendor أو package-lock، ولا مكتبة أو اعتماد جديد. تعديل package.json يضيف اختبارًا فقط.

## الملفات

التنفيذ: `app.js`, `dashboard.js`, `projects.js`, `task-engine.js`, `style.css`.

## التحقق

| الفحص | قبل التعديل | بعده |
| --- | --- | --- |
| npm install | ناجح | لا اعتماد جديد |
| npm test | 15 مجموعة PASS واختبارات ترحيل الخانات | 16 مجموعة PASS واختبارات ترحيل الخانات |
| npm run test:browser | ناجح | ناجح، مع اختبار الأدوات المباشرة الجديد و27 حالة مراجعة صفحات |
| performance.test.cjs ضمن التشغيل الكامل، day/projects/month | 68 / 126 / 48ms | 56 / 115 / 37ms |
| وسيط 7 تشغيلات متناوبة للنسخة السابقة والجديدة، day/projects/month | 48 / 117 / 32ms | 49 / 107 / 31ms |
| مشروع التفسير: عرض أولي / فتح جزء | 76 / 15ms | 87 / 17ms |
| مشروع التفسير: فتح الجميع / طي الجميع | 707 / 275ms | 729 / 311ms |

تحسن وسيط المشاريع بنحو 8.5% والشهر بنحو 3.1%. وسيط اليوم زاد 1ms؛ لا ادعاء بتحسن كل العروض أو ثباتها التام. مشروع التفسير في التشغيل الكامل أصبح أبطأ قليلًا مع إضافة أدوات فعلية لكل صف، مع بقاء الفروع المغلقة غير مرسومة. هذه قياسات محلية وليست ضمانًا للأجهزة الأخرى.

اختُبر Chromium 153.0.8010.0 بمسار تنفيذي مؤقت خارج المشروع. شملت التفاعلات مشروع التفسير الحقيقي المضمّن (30 أصلًا و240 فرعًا)، و20 فرعًا مفتوحًا، ومستويات متداخلة ومهمة مشتركة بين مشروعين. فُحصت النتيجة بضغطة وإلغاؤها، حفظ الخانات والتحقق منها، ثبات العقد والتركيز والارتفاع والتمرير، الترتيب، التحرير المباشر، والتوسيع عند العودة.

لقطات خاصة بالأدوات على سطح المكتب وعرض 820 و390 و320px، إضافة إلى 27 صورة للصفحات والمحرر. اختبارات الهاتف تتحقق من أبعاد 40px ومن أن الأدوات المعروضة قابلة للنقر وغير مغطاة في الصفوف المفحوصة. الاختبارات الأوسع تشمل RTL والتباين وreduced-motion ولوحة المفاتيح والتقويم والاستيراد والحذف الآمن.

لإعادة التشغيل:

```sh
npm install
npm test
WKT_CHROMIUM_EXECUTABLE=/absolute/path/to/chromium npm run test:browser
```

يمكن إضافة `WKT_SCREENSHOTS_DIR=/absolute/output/path` لحفظ الصور خارج المستودع.

## الحدود وما لم يكتمل

- الهاتف يستخدم مسارين ثابتين بدل سطر واحد بارتفاع 40–48px؛ تبقى جميع الأدوات ظاهرة دون طلبها.
- لم يتحقق شرط عدم زيادة أي زمن حرفيًا في كل القياسات؛ الأرقام التفصيلية أعلاه.
- Firebase والحساب اختُبرا بمحاكاة، دون دخول بحساب حقيقي أو مزامنة حية بين جهازين. لا ادعاء باختبار قارئ شاشة أو جهاز هاتف فعلي.
- لم يُنشر التطبيق أو تُدمج التغييرات إلى main؛ التسليم Pull Request للمراجعة.
