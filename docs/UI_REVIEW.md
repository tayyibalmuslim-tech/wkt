# مراجعة واجهة وقتي — المرحلة 5

المراجعة على فرع `ui-redesign`، فوق `264e8dd` مع إصلاحات المحرر والأسماء والمشاريع المشتركة. لا رفع أو دمج إلى main ضمن هذه المرحلة. مدة الخانة الحالية 10 دقائق واليوم 144 خانة، يبدأ من المغرب.

## حصيلة المراحل

| المرحلة | النتيجة |
| --- | --- |
| 0 | إعادة تنسيق HTML/CSS/JS في commit مستقل دون تغيير المنطق، وتسجيل الاختبارات والأداء. |
| 1 | متغيرات تصميم دافئة وهوية بنية، صف مهمة موحد، إجراءات عند الاختيار، وتسلسل هرمي بفروع تُنشأ عند الفتح فقط. |
| 2 | مساحة مشاريع بقائمة جانبية أو مبدّل، رأس مختصر، بحث يفتح مسار الفرع، ترتيب بالأرقام، وحفظ التوسيع والتمرير أثناء الجلسة. |
| 3 | لوحة مختصرة بقوائم اليوم والفائتة والمستقبلية وتحتاج توزيعًا، وفلاتر ومهمة سريعة، مع فصل مشاريع المهام عن المستقلة. |
| 4 | يومي أخف، فصل الفعلي والمطلوب، تحديث الخانات ونتائج الصلاة موضعيًا، تنقل سفلي، والحفاظ على التفاف مستطيلات الشهر. |
| 5 | تشغيل المتصفح فعليًا، فحص 27 صفحة/حجم، صور، إصلاح أهداف اللمس، توحيد أسطح الأقسام والأفعال والأيقونات والتركيز، وتحسين عرض المشاريع على التابلت. |

وصلت تعديلات أخرى أثناء العمل وحُفظت كما هي: أوزان تقدم المشروع، جمع تقديرات الأصل من الفروع، ترتيب الفروع، تعدد المشاريع، إخفاء المكتمل، وتوسيط المحرر واختصار حقوله وأزرار الأولوية 1–5. هذه ليست تغييرات منطق أجرتها المرحلة 5.

## تغييرات المراجعة النهائية

- صفحة الأقسام والأفعال تستخدم ألوان السطح والحدود وأنصاف الأقطار المشتركة بدل قيم مختلفة.
- عرض المشاريع يتحول للمبدّل حتى عرض 1050px؛ يمنع وجود قائمتين جانبيتين تضيقان أسماء المهام على التابلت.
- عناوين السعة في يومي ولوحة المهام أصبحت نصًا مساعدًا مختصرًا بدل خلفيات متكررة.
- أيقونات الإضافة والتكرار ومهام الصلاة SVG محلية؛ لا تعتمد على توافر محارف خاصة في الخط. تُعاد الاستفادة من HTML الأيقونات الثابت داخل الجلسة دون إدخاله في البيانات.
- توحيد تركيز الحقول والروابط وsummary. إصلاح لمس استيراد النسخة، وإغلاق المحرر، وخيار «بدون فترة محددة»، وأزرار الأولوية وخيارات المشاريع على الهاتف إلى 40px على الأقل في الحالات المفحوصة.
- دعم `WKT_CHROMIUM_EXECUTABLE` لاختيار متصفح اختبار محلي دون اعتماد جديد. تصحيح بيانات الاسم الطويل في اختبار الشهر كي لا تُعامل المهمة الطويلة المرتبة أولًا كمهمة قصيرة، وتحديث محدد حفظ المحرر بعد نقله إلى شريط الإجراءات.

الملفات: `app.js`, `dashboard.js`, `projects.js`, `task-engine.js`, `style.css`, `categories.css`, `tests/month-browser.cjs`, `tests/projects-browser.cjs`. الجديد: `tests/accessibility-browser.cjs` وهذا التقرير. تنسيق الاختبارات وCSS جزء من الفرق. لم تُعدل README أو قاعدة البيانات أو sync.js أو vendor أو package.json/package-lock.json، ولا التخزين أو الحسابات.

## الاختبارات والأجهزة

| الفحص | قبل تغييرات المرحلة 5 | النتيجة النهائية |
| --- | --- | --- |
| npm install | ناجح | لا اعتماد جديد في المشروع |
| npm test | ناجح، 15 مجموعة PASS واختبار ترحيل الخانات | ناجح، المجموعات نفسها |
| npm run test:browser | متعذر لغياب Chromium | ناجح مع Chromium 153.0.8010.0 ومسار تنفيذي محدد بالبيئة |
| فحص المتصفح الموسع | لم يكن موجودًا | 27 حالة ناجحة، و27 صورة |
| git diff --check | — | ناجح |

الأحجام: سطح مكتب 1440×1080، تابلت 820×1180، هاتف 390×844. تشمل الصور: يومي، لوحة المهام، المشاريع، الشهر، الأقسام والأفعال، المتكرر، الإعدادات، الحساب، ومحرر المهمة. توجد أيضًا اختبارات الصفوف عند 1920×1080 و390/320px، واختبارات التقويم على سطح المكتب والهاتف.

الفحص الموسع يتحقق من RTL، غياب تجاوز عرض الصفحة، ظهور زر تنزيل النسخة، أسماء الأزرار، تباين النصوص المعروضة (4.5:1، أو 3:1 للنص الكبير)، وأبعاد أهداف اللمس على الهاتف. يشمل المحرر وخيارات المشاريع والأولوية وحالات فعلتها/لم أفعلها/غير مسجلة. ليست هذه شهادة امتثال شاملة لـWCAG أو اختبار قارئ شاشة.

اجتازت اختبارات المتصفح كذلك كثافة 15 صفًا على الأقل في شاشة 1080px، الفروع الكسولة والمتعددة، قراءة النص الكامل، الترتيب والبحث والاستيراد والحذف الآمن، حفظ التركيز والتمرير، reduced-motion، التفاف مستطيلات الشهر والقائمة العائمة بثلاثة إجراءات وإغلاقها بـEscape. فُحص تنزيل ملف JSON فعلي وفتح نموذج الدخول والإنشاء بمحاكاة Firebase.

لإعادة التشغيل في بيئة لديها Chromium:

```sh
npm install
npm test
WKT_CHROMIUM_EXECUTABLE=/absolute/path/to/chromium npm run test:browser
```

اختياريًا: `WKT_SCREENSHOTS_DIR=/absolute/output/folder` لحفظ الصور وaudit.json. الصور لا تُحفظ داخل المستودع. المتصفح المؤقت وأداة التنسيق خارج المشروع؛ لا CDN أو build جديد.

## الأداء

الاختبار الأصلي `tests/performance.test.cjs` لم يتغير. أول قياس عند بداية المرحلة 5 على النسخة الأحدث حينها: اليوم 43ms / المشاريع 147ms / الشهر 37ms. بعد وصول إصلاحات المحرر وقبل تطبيق المراجعة: 48 / 131 / 36ms. التشغيل النهائي الكامل: 54 / 132 / 55ms؛ تتذبذب التشغيلات المنفردة، فلا تُستخدم وحدها لإثبات تحسن.

مقارنة عادلة للمرحلة 5: نسختان بنفس منطق المهام والخانات وإصلاحات المحرر، قبل المراجعة وبعدها، 7 تشغيلات متناوبة لكل نسخة مع عكس الترتيب بين الدورات. الوسيط:

| العرض | قبل المراجعة ms | بعد المراجعة ms |
| --- | ---: | ---: |
| day | 48 | 45 |
| projects | 116 | 111 |
| month | 35 | 31 |

لم يزد أي وسيط في هذه العينة. مسح السجل بقي مرتين لكل عرض واستدعاءات اليوم 2 / 2 / 4. الرسم الكسول والتحديثات الموضعية ما زالت مجتازة. هذه قياسات jsdom وليست قياسات سرعة هاتف فعلي أو ضمانًا لكل تشغيل.

مقارنة المرحلة 0: وسيط 7 تشغيلات بعد التنسيق المسجل حينها كان 46 / 334 / 53ms. مقابل 45 / 111 / 31ms الآن: اليوم أقل بنحو 2%، المشاريع 67%، والشهر 42%. أول قياس قبل أي عمل كان 44 / 329 / 42ms؛ اليوم الحالي أعلى منه 1ms، والمشاريع أقل 218ms، والشهر أقل 11ms. تغيرت المدة من 15 إلى 10 دقائق (96 إلى 144 خانة) ووصلت ميزات وحسابات جديدة؛ لذلك المقارنة التاريخية وصفية وليست تجربة معزولة تثبت أثر الواجهة وحدها.

## المتبقي والمخاطر

- لم يُختبر حساب Firebase حقيقي أو مزامنة بين جهازين أو صلاحيات الإنتاج. المحاكاة لا تثبت ذلك.
- Chromium على Linux ومحاكاة أحجام شاشة فقط؛ لا جهاز هاتف فعلي أو Safari/Firefox أو قارئ شاشة.
- ألوان الأفعال التي يختارها المستخدم قد تحتاج فحص تباين مستقل. الفحص يغطي البيانات التجريبية والحالات المعروضة، وليس كل لون محتمل أو حالة تفاعل.
- النص الطويل يُقص في الصف؛ النص الكامل متاح عند اختياره/تحريره. القوائم الضخمة المفتوحة كلها أغلى من الفروع المغلقة؛ اختبار التفسير يغطي 270 مهمة، لا كل حجم ممكن.
- لا تثبت العينات أن زمن كل تشغيل لن يزيد. تحسنت الوسائط في المقارنة الحالية، مع بقاء تقلبات الجهاز واضحة.

الصور وaudit.json وعينات الأداء والتقرير مُرفقة في حزمة مستقلة خارج المستودع. لا تتضمن بيانات حساب حقيقي.
